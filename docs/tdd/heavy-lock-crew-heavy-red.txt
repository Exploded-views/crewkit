The rule (GREEN b1c9bc7): never convert a held lock. proof() never calls flock on an inherited
descriptor, not even in the same mode: a LOCK_SH probe on an exclusive holder's descriptor would
downgrade it. It needs an inherited descriptor on the lock file, and the lock held right now,
read with fresh descriptors it opens itself (a new open file description conflicts with every
inherited lock) and releases at once. A fresh LOCK_EX|LOCK_NB must fail; if a fresh LOCK_SH|LOCK_NB
then succeeds the holder is shared and an inherited, held heavy.slot1/2 in the lock's directory is
also required; if it fails the holder is exclusive (bench, raw flock) and that is a hold.

Documented residual (heavy_lock.py docstring; pinned by test_residual_an_unlocked_fd_passes_...):
an inherited descriptor that is open but NOT locked passes while someone else holds the lock,
because the probes see a held lock, not whose it is. The check is advisory.

Scope: enforced where the default crew state dir exists, OR where a configured lock's directory
does ("either dir", the agreed rule); elsewhere it passes as "no crew state dir: unguarded". The
lock path is the user-only `heavy_lock` setting (a configured path moves the lock, and can't
switch the check off while the default dir exists). CREWKIT_HEAVY_LOCK is honoured only with
CREWKIT_HEAVY_LOCK_TEST=1.
